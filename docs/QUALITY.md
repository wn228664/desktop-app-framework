# 代码质量与注释规范

## 实现要求

- 自有代码仅 JavaScript / Vue，统一 ESM；preload 构建为沙盒可用的 CommonJS。
- 先使用平台和成熟库已有能力。封装只统一明确的重复契约，不建立没有调用方的抽象层。
- 公共接口参数有范围、单位、默认值和失败行为；系统权限边界必须在主进程重新校验。
- 只读 props，事件上交状态变更。组件不隐藏业务请求、业务成功判断或全局副作用。
- 异步动作同步防重复，支持取消/卸载，忽略过期结果。写操作不自动重放。
- 错误可见且可恢复：表单失败保留输入，加载失败能重试，未配置能力有明确状态。
- 事件、定时器、文件句柄、授权和临时文件均有清理位置，任务与响应体有大小/时间上限。
- 根页面不滚动；内容、表格和浮层各自管理滚动。保持键盘焦点、对比度和系统窗口行为。
- 不把测试数据当真实服务结果，不包含原项目标识、接口、素材、账号或业务状态码。

## 注释要求

使用自然、简洁的中文解释公共契约、权限、单位、竞态和必要的取舍。代码可以直接表达的逐行操作无需注释；不写空泛的“初始化”“处理数据”“提高性能”，不保留作者聊天、自我评价或失效 TODO。

本项目源码按以下具体标准维护：

- 公共函数和服务方法使用 JSDoc，说明调用场景、参数类型/单位/默认值/范围、返回值、正常空态、异常与副作用。
- Vue 通用组件在源码中说明职责、Props 默认值、事件载荷、插槽、暴露方法、取消/卸载行为和接入示例，不能只让使用者去翻 README。
- 窗口、IPC、请求、文件、凭据和任务代码解释权限归属、状态所有权、并发时序、资源释放与失败恢复，注释放在对应责任链附近。
- 页面入口说明示例数据和副作用的范围；构建配置说明默认策略、重新构建要求、签名与发布关系。
- 布局注释说明高度来源、内部滚动和缩放重排，不逐个翻译样式声明；测试注释区分真实实现与注入替身的验证边界。

JSON 配置保持合法 JSON，字段用途在读取它的构建/入口源码与文档中说明，不能为了加注释破坏配置语法。本次源码注释整理与语义核对见 [COMMENT_REVIEW.md](COMMENT_REVIEW.md)。

例如上传任务说明真实进度限制；文件读取说明为什么需要二次 stat 和有界读取；原子写说明失败不会截断旧文件。组件 props 与 emits 可直接看见类型和默认值，更复杂的输入/输出形状放在组件说明与 docs 中。

修改公共契约时同步更新对应测试与文档。不要为了注释覆盖率给每个 import、ref 或样式块加机械注释。

## 验证命令

```sh
npm ci
npm run verify
npm run test:e2e
npm audit --omit=dev
npm audit
```

ESLint 检查 JS 与 Vue 规则；格式由 Prettier 统一，两者冲突的纯排版规则关闭，语义规则保留。Node Test 覆盖错误、权限、取消、存储和传输边界；Playwright 启动真实 Electron 验证沙盒、路由、组件与布局。

E2E 通过 `DESKTOP_TEST_USER_DATA` 使用隔离临时目录，结束后清理；此覆盖只在非安装包模式生效。测试不写用户真实文件，不启用系统登录项或托盘。需要验证文件对话框时可在 Electron 测试进程中替换对话框选择结果，不给产品增加测试后门。

## 安全与依赖

npm audit 是已知依赖告警，不是完整安全证明。运行时与开发工具分别记录，禁止使用 `npm audit fix --force` 自动降级整个工具链。漏洞修复采用兼容版本升级，并重新检查 lint/test/build/安装包。

开发工具仍可能处理仓库输入；只在可信工作区运行构建，不给不可信文件名、表达式或构建配置开放执行权限。当前锁文件审计与例外见 DEPENDENCIES.md，实际交付验证见 VALIDATION.md。

## 验收边界

本地单测、真实 Electron 交互、本机应用包启动、Windows 产物生成、Windows 实机安装、签名、公证和在线更新是不同证据。记录具体机器、命令、结果与未覆盖项，不互相替代。
